## Запуск

Требуется Python **3.10 или новее**. Программа использует стандартную библиотеку; pytest и flake8 нужны для проверки.

Распакуйте архив и откройте терминал в каталоге `incident_project`:

```bash
python -m pip install -r requirements.txt
python main.py
```


## Возможности

Сохранены регистрация, просмотр, поиск без учета регистра по названию/описанию, фильтрация по статусу и приоритету, сортировка по убыванию приоритета, назначение исполнителя, изменение статуса, статистика и JSON-хранилище. Добавлена полная карточка инцидента (пункт 9), показывающая связанные объекты.

Приоритеты: 1 — низкий, 2 — средний, 3 — высокий. Статусы: Новый, В работе, Решен, Закрыт. Новый инцидент без исполнителя получает статус «Новый», с исполнителем — «В работе». Назначение переводит в работу только новый инцидент. После проверки логики действуют правила: «Новый» допустим только без исполнителя; остальные статусы требуют исполнителя. Закрытый инцидент можно открыть переводом в «В работе»; переназначать его разрешено только после открытия. Пропуск стадии «Решен» при закрытии разрешен как упрощение учебной модели.

## Анализ предметной области и классы

| Класс | Атрибуты | Поведение |
| --- | --- | --- |
| `User` | `name` | `__init__`: проверка имени; `__str__`: представление автора |
| `Executor(User)` | унаследованный `name` | наследует конструктор; переопределяет `__str__` |
| `Incident` | `id`, `title`, `description`, `user`, `priority`, `created_at`, `_executor`, `_status` | конструктор, `assign_executor()`, `change_status()`, `__str__`; свойства `executor`, `status`, `priority_name` |

В памяти используется `list[Incident]`. `incident.user` содержит объект `User`, а `incident.executor` — объект `Executor` или `None`, а не строку имени. Один пользователь или исполнитель может участвовать в нескольких инцидентах.

Инкапсуляция: статус и исполнитель доступны через свойства только для чтения, изменяются методами с проверками. Наследование: `Executor` является специализацией `User`. Полиморфизм: `print(item.user)` и `print(item.executor)` вызывают разные реализации `__str__`. Декоратор `@property` применяется для контролируемого доступа к состоянию.



## Структура

- `main.py` — меню, ввод и вывод, обработка ошибок;
- `models/users.py` — классы `User` и `Executor`;
- `models/incident.py` — класс `Incident`;
- `models/__init__.py` — экспорт классов;
- `incidents.py` — создание и обработка коллекций;
- `storage.py` — загрузка/сохранение;
- `utils.py` — безопасный числовой ввод;
- `data/incidents.json` — исходный инцидент из ПР1–ПР2;
- `tests/` — проверки объектов, коллекций и хранения;
- `REPORT_PR3.md` — краткое описание выполненной проектной части;
- `requirements.txt`, `pytest.ini`, `.gitignore` — настройки проверки и Git.

## JSON и совместимость

Сохранен формат ПР2: список записей с полями `id` (положительное целое), `title`, `description`, `user` (имя), `executor` (имя или null), `priority` (1–3), `status`, `created_at` (ISO 8601). Отдельная миграция корректного исходного файла не требуется. Старые записи с противоречивым статусом (например «Закрыт» без исполнителя) отклоняются, а не исправляются молча. Данные всегда читаются относительно расположения `main.py`.

Загрузчик создает объекты и объединяет ссылки по паре «роль + имя». В учебной версии одинаковые имена в одной роли считаются одним человеком; учет полных тезок и отдельные ID пользователей — задача дальнейшего развития. Словари остаются только на границе JSON и для статистики.

Отсутствующий файл означает пустую коллекцию. Поврежденный JSON, неверные поля и повторные ID приводят к понятному сообщению и остановке загрузки без перезаписи исходного файла. Сохранение выполняется после изменений и при обычном выходе: запись во временный файл и атомарная замена основного. Если запись не удалась, изменение откатывается: сохраняются прежние данные в памяти и на диске. После устранения ошибки нужно повторить операцию.

## Проверки

```bash
python -m pytest -v
python -m flake8 .
```

Тесты проверяют создание, связи объектов, наследование, строковое представление, изменение состояния, ошибочные значения, функции коллекций, совместимость с JSON ПР2, восстановление общих ссылок и защиту файла при ошибке записи.
